# ADR-001: 订阅中"信息节点"展示方式保留现状

- **状态**: 已接受（延后重构）
- **日期**: 2026-08
- **关联**: 架构审计问题 E（`ClientController::setSubscribeInfoToServers`）

## 背景

当前实现将"剩余流量/套餐到期/重置倒计时"伪造成节点条目插入订阅列表头部
（复制 `$servers[0]` 的真实节点配置仅修改名称），用户客户端可以真实连接这些"节点"。
这是绕过式的展示方案，但已被现有前端主题与部分客户端依赖。

## 候选方案

1. **保留现状**（本决策）：不动实现，仅记录风险。
2. **Subscription-Userinfo 响应头**：标准做法，Singbox 生成器已输出该头
   （`app/Protocols/Singbox/Singbox.php::handle`），但 Clash/Surge 等其他协议类未统一，
   且用户已习惯在节点列表看到信息，改变展示位置属于产品行为变更。
3. **独立信息位/虚拟协议**：需要客户端支持，成本最高。

## 决策

本期修复（审计 FIX-13g）不改实现，原因：

- 涉及前端主题与多协议客户端联动，收益不抵回归风险；
- 该功能由配置开关 `show_info_to_server_enable` 控制，默认关闭，管理员可自行关闭。

## 后续迭代触发条件

- 出现用户误连信息节点导致的投诉或工单；
- 订阅协议层统一重构时（所有协议类补齐 Subscription-Userinfo 头），一并移除信息节点逻辑。
